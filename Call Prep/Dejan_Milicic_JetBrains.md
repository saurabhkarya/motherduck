## Discovery Questions

### 1. Understand the Context
```
"What brought you to MotherDuck? Is this for JetBrains
work, or more of a personal exploration?"

"Are you building anything data-related on the IntelliJ
Platform side?"
```

### 2. JetBrains Internal Use
```
"What does JetBrains use internally for analytics?
Telemetry, product usage data, that kind of thing?"

"Is there any crossover with DataGrip or database tooling?"
```

### 3. RavenDB Background
```
"With your RavenDB experience, how do you think about
the document DB vs. analytical DB space?"

"Are you seeing teams use both for different workloads?"
```

### 4. Community/Content
```
"Are you writing or speaking about anything data-related?
Happy to support if there's content we could collaborate on."
```

## Key Talking Points

### 1. DuckDB for Developer Workflows
```
"A lot of developers love DuckDB for local analytics—

with cloud scale and collaboration."
```

### 2. Database Expert Appeal
```
"With your RavenDB background, you'll appreciate the
architecture. Columnar storage, vectorized execution,
optimized for analytical queries."
```

### 3. IDE Integration Potential
```
"If there's ever interest in tighter DataGrip integration
or IntelliJ database tooling, we'd love to chat. DuckDB
is becoming popular with developers."
```

## Anticipated Objections

### "This is personal exploration, not JetBrains"
```
YOU: "Totally fine! A lot of our best advocates started
that way. If you end up liking it, happy to chat about
JetBrains use cases too."
```

### "JetBrains has its own data infrastructure"
```
YOU: "Makes sense for a company that size. Is there any
team that might benefit from faster ad-hoc analytics?
Sometimes it's a complement, not a replacement."
```

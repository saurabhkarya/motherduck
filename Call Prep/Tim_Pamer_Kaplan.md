## Discovery Questions (Tailored for Tim)

### 1. Understand Their Current Work
```
"What's your main focus at Kaplan right now? Still heavy on the
forecasting and analytics side, or has that shifted?"

"How's your team structured—are you mostly building models,
or doing more of the data engineering/pipeline work too?"
```

### 2. Probe Current Stack / Pain
```
"What's your current data warehouse setup at Kaplan?
Snowflake, BigQuery, something on-prem?"

"How do you feel about the iteration speed when you're
building models? Any bottlenecks in the feedback loop?"
```

### 3. Sizing Questions
```
"Roughly how much data are you working with?

"How many people on your team are running queries regularly?"

### 4. Enterprise Context (Critical for Kaplan)

go through a central IT/platform team?"
```

## Key Talking Points for Tim

### 1. Speed for Iterative Analytics
```
"One thing our users love—especially folks doing forecasting
and model iteration—is the query speed. You can run complex
aggregations in milliseconds, so that feedback loop tightens up.

No more waiting 30 seconds to see if your feature worked."
```

### 2. DuckDB Foundation (He'll Appreciate This)
```
"Under the hood, we're built on DuckDB—so if you've played
with that locally, MotherDuck is basically that, but with
cloud scale, sharing, and collaboration built in.

Same SQL, same speed, but now your whole team can access it."
```

### 3. Cost vs. Snowflake/Databricks
```
"If you're on Snowflake or Databricks, we typically see
60-70% cost savings for analytical workloads.

The pricing model is simpler too—no credit burn surprises."
```

### 4. Python/Notebook Integration (if relevant)
```
"If your team works in notebooks, we integrate directly.
You can query MotherDuck from Python, Jupyter, whatever
your ML workflow looks like—no extra connectors needed."
```

## Anticipated Objections

### "We're already on Snowflake/Databricks"
```
YOU: "Totally get it—most of our customers started there too.
Quick question: are you happy with the cost and query speed
for your analytical workloads?

A lot of teams use MotherDuck alongside their existing DWH
for the fast, iterative stuff—not as a rip-and-replace."
```

### "I'd have to go through IT/procurement"
```
YOU: "Makes sense for a company like Kaplan. Here's what usually
works: our SA can do a quick technical session with you first,
just to see if it's even worth bringing to IT.

That way you're not wasting anyone's time if it's not a fit.
Would that make sense?"
```

### "I don't have time to evaluate new tools right now"
```
YOU: "I hear you—analytics leaders are stretched thin.
Tell you what: could I send you a 2-minute video that shows
the DuckDB-to-MotherDuck workflow?

If it looks interesting, we can revisit when timing's better.
If not, no hard feelings."
```

## Key Talking Points for Craig

### 1. Technical Architecture Story (Lead with This)
```
"MotherDuck is built on DuckDB—it's a fundamentally
different architecture than Hadoop or Snowflake.

Instead of distributed clusters that coordinate across
nodes, we optimize for single-node performance. Each
user gets isolated compute. Sub-100ms cold starts.

For most analytical workloads—even at TB scale—this
beats distributed systems on both speed and cost."
```

### 2. Hadoop Modernization (If Relevant)
```
"If you're still running Hadoop workloads, you might
find this interesting. Teams are moving batch jobs
that took hours to MotherDuck and running them in
minutes.

No more cluster management, no more YARN tuning. Just
write SQL and it runs."
```

### 3. Enterprise Credibility
```
"We're founded by the team behind Google BigQuery—
Jordan Tigani was one of the original engineers.
Backed by a16z and Redpoint.

We're SOC 2 Type II certified, and we work with
enterprise teams who care about security and governance."
```

### 4. Hybrid Execution (Developer Experience)
```
"One thing Java developers appreciate: DuckDB runs
locally. You can develop and test on your laptop,
same SQL, same engine. Then query cloud data when
you need scale.

No waiting for cluster spin-up during development."
```

## Anticipated Objections

### "GM has established vendor relationships"
```
YOU: "Totally understand—enterprise procurement is
complex. I'm not suggesting you rip and replace.

But for specific use cases—maybe analytics that don't
need petabyte scale, or developer tooling—there might
be room for something simpler alongside what you have.

What workloads would be candidates for trying something
different?"
```

### "We're happy with our current setup"
```
YOU: "That's great. Can I ask what you're using today?
I'm always curious how enterprise teams are solving
these problems.

[Listen, learn, note for future]

If anything changes, I'd be happy to reconnect."
```

### "I don't have time for vendor calls"
```
YOU: "Totally respect that. I'll keep this brief.

One question: is there anything in the data space
that's been frustrating you lately? If MotherDuck
is relevant, great. If not, I won't waste your time."
```

### "What's MotherDuck? Never heard of it."
```
YOU: "Fair—we're newer, but not inexperienced. Founded
by the BigQuery team, built on DuckDB which is the
fastest-growing database engine in the industry.

Given your architecture background, you might find
the technical approach interesting. Happy to send
a link to our architecture docs if you want to dig in."
```

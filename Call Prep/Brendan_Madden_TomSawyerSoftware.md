## Key Talking Points for Brendan

### 1. Technical Architecture (Lead with This)
```
"Given your research background at IBM, you'll appreciate
this: MotherDuck is built on DuckDB, which takes a fundamentally
different approach than distributed systems.

Instead of coordinating across nodes, we optimize for single-node
performance. Each query gets isolated compute. Sub-100ms cold
starts. For most workloads—even complex graph analytics—this
beats distributed systems on both speed and simplicity."
```

### 2. Graph Data Alignment
```
"Graph data often has complex query patterns—multi-hop joins,
aggregations across relationships. DuckDB handles that really
well because of its columnar architecture and vectorized
execution.

If you're doing any analytics on graph metadata or relationship
data, MotherDuck would be a natural fit."
```

### 3. Enterprise Software Company Value Prop
```
"We work with a lot of enterprise software companies like
Tom Sawyer. Common use cases:

- Product analytics (who's using what features)
- Customer health scoring
- Internal ops reporting
- Demo environments for sales

MotherDuck is 70% cheaper than Snowflake and way simpler.
No warehouse management, no sizing decisions."
```

### 4. Longevity and Stability
```
"I noticed you've been building Tom Sawyer for over 30 years.
We value that kind of long-term thinking too.

MotherDuck is founded by the team behind Google BigQuery—
Jordan Tigani was one of the original engineers. Backed by

chasing hype cycles."
```

### 5. Developer Experience (Engineers Will Love It)

## Anticipated Objections

### "We're a small company, don't need much"
```
YOU: "That's actually our sweet spot. MotherDuck is built for
teams that don't need petabyte scale but want the convenience
of a managed service.

Our free tier has 10GB storage and 10 compute hours—that
might be all you need for internal analytics. Worth a look?"
```

### "We've been doing fine without a data warehouse"
```
YOU: "After 34 years, you clearly know what works. I'm not
suggesting you need something new if things are working.

But if there's ever friction—reports taking too long, data
scattered across systems, engineers wasting time on infra—
MotherDuck removes that overhead. Just SQL, no management."
```

### "What's MotherDuck? Never heard of it."
```
YOU: "Fair—we're newer but not inexperienced. Founded by the
BigQuery team at Google, backed by a16z and Redpoint.

We're built on DuckDB, which has become incredibly popular
in the data community. Given your technical background, you
might find the architecture interesting."
```

### "We use [X] for analytics"
```
YOU: "Got it. What are you using?

[Listen]

A lot of teams keep their existing tools for specific use
cases but add MotherDuck for fast ad-hoc queries and
development work. It's simple enough that it doesn't add
overhead—might complement what you have."
```

### "I don't have time for vendor calls"
```
YOU: "Totally respect that—34 years running a company means
your time is valuable.

Quick question: is there any data challenge at Tom Sawyer
that's been annoying you? If MotherDuck is relevant, I'll
explain in 2 minutes. If not, I'll let you go."
```

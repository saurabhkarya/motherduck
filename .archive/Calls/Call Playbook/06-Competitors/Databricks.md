# Handling Databricks
**When they use or mention Databricks**

---

## The Qualification Question
```
"Databricks is great for heavy ML workloads."

"Quick question - what's your primary use case? ML/AI or analytics?"
```

---

## If Analytics-Focused
```
"For analytics, MotherDuck is simpler and more cost-effective."

"You're paying for Spark complexity and ML features you may not need."
```

---

## Landmine Questions
Plant these to surface pain:
- "How long does it take to run a simple ad-hoc query?"
- "Do you need Spark for your analytics use case?"
- "What percentage of workloads are ML vs. analytics?"

---

## Key Differentiators
| Databricks | MotherDuck |
|------------|------------|
| Spark-based (complex) | SQL-first (simple) |
| Built for ML + Analytics | Optimized for Analytics |
| Higher overhead | Lightweight |
| Higher learning curve | Know SQL? You're set |

---

## When Databricks Makes Sense
- Heavy ML/AI workloads
- Already invested in Spark ecosystem
- Petabyte-scale data science

---

## When MotherDuck Wins
- Pure analytics use cases
- Teams that don't need Spark
- Cost-conscious organizations
- Faster time-to-query
